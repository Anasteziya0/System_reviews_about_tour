# Система отзывов об экскурсиях

Система отзывов об экскурсиях на Python с веб-интерфейсом на Django.

## 1. Назначение проекта

Приложение предназначено для сбора, хранения и просмотра отзывов об экскурсиях.
Проект позволяет хранить сведения об экскурсиях, пользователях и отзывах, выполнять основные операции с этими объектами и предоставлять доступ к информации через веб-интерфейс Django.

Проект развивается поэтапно: консольная версия приложения дополняется веб-интерфейсом и постепенно переводится на возможности Django.

## 3. Предметная область

В системе используются три основные сущности:

- Экскурсия (`Tour`) – идентификатор, название, место, цена и длительность;
- Пользователь (`User`) – идентификатор, имя и адрес электронной почты;
- Отзыв (`Review`) – идентификатор, экскурсия, пользователь, оценка от 1 до 5, комментарий и дата.

Пользователь оставляет отзыв об экскурсии. Оценка 4–5 считается положительной, 3 – нейтральной, 1–2 – отрицательной. Средний рейтинг экскурсии считается по всем её отзывам.

Для предметной области реализованы собственные Python-классы.
На текущем этапе данные хранятся в JSON-файлах. Django ORM и база данных приложения пока не используются.

## 5. Веб-интерфейс

Веб-часть приложения реализована на Django.

Основные страницы:

| URL | View-функция | Шаблон | Назначение |
|---|---|---|---|
| `/` | `homepage.views.index` | `homepage/index.html` | главная страница |
| `/tours/` | `tours.views.tours` | `tours/tour_list.html` | список экскурсий |
| `/tours/<int:tour_id>/` | `tours.views.tour_detail` | `tours/tour_detail.html` | информация об экскурсии и средний рейтинг |
| `/reviews/` | `reviews.views.reviews` | `reviews/review_list.html` | список отзывов |
| `/reviews/<int:review_id>/` | `reviews.views.review_detail` | `reviews/review_detail.html` | информация об отзыве |
| любой другой адрес | `homepage.views.page_not_found` | `homepage/page_not_found.html` | собственная страница 404 |

Если экскурсия или отзыв с указанным идентификатором не найдены, страница показывает соответствующее сообщение, а HTTP-ответ имеет статус 404.

Для формирования страниц используются Django-шаблоны.
Генерация HTML непосредственно в Python-коде веб-представлений не используется. Функция `page()` больше не используется веб-представлениями и удалена.
Представления подготавливают данные и передают их в шаблоны через контекст.

Операции добавления экскурсий и отзывов, поиска, сортировки и статистики реализованы в консольной версии. В веб-интерфейсе они появятся после реализации форм.

## 6. Django Template Language

Шаблоны используют возможности Django Template Language.

### Базовый шаблон

Общий шаблон страниц:

```text
templates/base.html
```

Он содержит общую HTML-структуру страницы, подключение Bootstrap, собственных стилей и JavaScript, логотип, навигацию, подвал и блоки для содержимого отдельных страниц.

Дочерние шаблоны используют наследование:

```text
{% extends "base.html" %}
```

Содержимое отдельных страниц размещается в блоке `content`, заголовок страницы задаётся блоком `title`:

```text
{% block title %}
{% endblock %}

{% block content %}
{% endblock %}
```

### Включаемые шаблоны

Повторяющиеся фрагменты вынесены в отдельные шаблоны:

- `templates/includes/navigation.html` – навигация сайта;
- `tours/includes/tour_card.html` – карточка экскурсии;
- `reviews/includes/review_status.html` – статус отзыва (положительный, нейтральный, отрицательный).

Подключение выполняется с помощью:

```text
{% include "tours/includes/tour_card.html" %}
{% include "reviews/includes/review_status.html" %}
```

### Контекст

Представления передают данные в шаблоны через словарь контекста. Например, для списка экскурсий:

```python
context = {
    "tours": tours_list,
}
```

В шаблоне данные доступны по имени переменной:

```text
{% for tour in tours %}
```

Для страницы отдельной экскурсии используется переменная `tour`, для страницы отзыва – `review`.

### Циклы и условия

Для формирования списков используются циклы `{% for %}`; при отсутствии элементов используется `{% empty %}`.
Условия `{% if %}` используются для отображения различного содержимого: найден или не найден объект, наличие отзывов у экскурсии, статус отзыва по оценке.

## 7. Фильтры шаблонов

В шаблонах используются стандартные фильтры Django Template Language:

- `{{ tours|length }}` – количество экскурсий;
- `{{ tour.name|default:"Без названия" }}` – значение по умолчанию;
- `{{ rating|floatformat:1 }}` – формат среднего рейтинга.

Фильтры используются для представления данных и не содержат бизнес-логику приложения.
Дата отзыва на текущем этапе хранится как строка и выводится без преобразования средствами шаблона.

## 8. URL-маршрутизация

Для страниц используются именованные маршруты Django и пространства имён приложений (`app_name`):

```text
homepage:index
tours:list
tours:detail
reviews:list
reviews:detail
```

Ссылки в шаблонах формируются через `{% url %}`, а не жёстко заданными адресами:

```text
{% url 'tours:list' %}
{% url 'tours:detail' tour.id %}
{% url 'reviews:list' %}
{% url 'reviews:detail' review.id %}
```

Статические файлы проекта находятся в каталоге `homepage/static/homepage/`:

## 10. Хранение данных

На текущем этапе данные приложения хранятся в JSON-файлах:

- `data/tours.json`;
- `data/users.json`;
- `data/reviews.json`.

Загрузка данных выполняется средствами модуля `storage.py`. Предметные объекты создаются на основе собственных Python-классов из каталога `models/`.
В `reviews.json` вместо объектов хранятся идентификаторы `tour_id` и `user_id`, по ним при загрузке восстанавливаются связи.

Django ORM на текущем этапе не используется. Формы Django не реализованы. Работа с базой данных относится к следующим практическим работам.

## 11. Основные модули

- `storage.py` – загрузка и сохранение данных в JSON, преобразование JSON ↔ объекты;
- `models/` – классы предметной области `Tour`, `User`, `Review` и функции работы с ними;
- `main.py` – консольный вариант работы с приложением;
- `utils.py` – вспомогательные функции консольного ввода;
- `tours/views.py` – веб-запросы, связанные с экскурсиями;
- `reviews/views.py` – веб-запросы, связанные с отзывами;
- `homepage/views.py` – главная страница и страница 404.

## 14. Запуск проекта

Подготовка (один раз):

```text
py -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python manage.py migrate
```

Для запуска Django-сервера необходимо перейти в каталог проекта и выполнить:

```text
python manage.py runserver
```

После запуска веб-интерфейс доступен по адресу:

```text
http://127.0.0.1:8000/
```

Консольная версия приложения:

```text
python main.py
```
